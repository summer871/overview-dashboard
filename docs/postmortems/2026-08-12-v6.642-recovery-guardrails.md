## Do not repeat these mistakes
1. Do not change the shared layout engine to fix a localized card-placement problem.
2. Do not treat syntax/hash/unit/fixture checks as proof that persisted browser layout is safe.
3. Do not call a recovery successful until the full real `/dev` page passes hard-refresh QA in the same browser with existing persisted state.
4. Do not declare success from a partial screenshot; inspect full page extent and footer/build identity.
5. Treat Git source, Apps Script head, production, browser cache, and browser-persisted layout as separate states.
6. Do not bundle layout work with attribution/data-path work.
7. Do not clear/reset localStorage, IndexedDB, saved layout, or other browser state without separate authorization and an exact pre-change snapshot.
8. If handoff/server/runtime state disagrees, stop and diagnose read-only before changing code.
9. After a visual regression, restore the proven checkpoint before attempting another feature change.
10. Do not rerun the historical root-attribution backfill or rebuild the browser-ready cache because of a UI/layout failure.
11. Recovery checks must target only intended files; unrelated untracked files stay untouched.
12. Do not paste large recovery programs interactively into PowerShell; use small inspectable commands or a saved `.ps1` only when needed.
13. Do not use GitHub/ClickUp writes as capability tests or placeholders.
14. Future improvements must be isolated one at a time with a specific rollback point and real `/dev` acceptance before the next change starts.
