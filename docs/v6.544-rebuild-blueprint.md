# v6.544 Dashboard Component Rebuild Blueprint

Status: implementation contract
Branch: `agent/v6.544-tat-table-rebuild`

## Purpose

Rebuild dashboard tables and charts from a new shared component system. This is not a restyle, wrapper, compatibility adapter, or legacy-DOM preservation project.

## Non-negotiable rules

1. Do not wrap or adopt legacy TAT, Remake, or Overview cards.
2. Do not keep legacy card markup and apply shared classes afterward.
3. Do not add adapter files, proxy constructors, mutation observers, or DOM patching to make old components look shared.
4. Do not use tab-specific visual implementations for the same component type.
5. Do not remove existing data logic or user-facing functionality.
6. Custom behavior must be expressed through shared-component configuration or explicit extensions.
7. No `/dev` push until the reference rebuild passes repository validation.
8. No release merge or footer version bump until all registered components are migrated and browser-tested.

## Shared component architecture

### Shared card shell

A single card renderer owns:

- outer border, radius, background, and spacing;
- title and subtitle placement;
- action toolbar placement;
- loading, empty, and error states;
- collapsed and expanded states;
- responsive behavior;
- pop-out trigger placement.

Required API shape:

```javascript
cdaCard.render({
  key,
  host,
  title,
  subtitle,
  actions,
  body,
  state,
  wide,
  collapsible
});
```

### Shared table component

A single table renderer owns:

- table DOM creation;
- headers and sort controls;
- typography, padding, borders, and alignment;
- column chooser;
- selection and pinned rows;
- child rows;
- totals;
- loading, empty, and error states;
- CSV export;
- responsive behavior.

Data and behavior are supplied through configuration.

Required API shape:

```javascript
cdaTable.register({
  key,
  host,
  columns,
  rows,
  rowKey,
  defaultSort,
  selection,
  childRows,
  totals,
  onRowClick,
  export
});
```

### Shared chart component

A single chart renderer owns:

- card and canvas DOM creation;
- title, subtitle, and action toolbar;
- typography, palette, axes, grid, legend, and tooltip defaults;
- loading, empty, and error states;
- selection and dimmed states;
- CSV, PNG, copy-image, reset, and pop-out actions;
- responsive sizing;
- Chart.js creation and destruction.

Data and behavior are supplied through configuration. Existing chart instances must not be adopted.

Required API shape:

```javascript
cdaChart.register({
  key,
  host,
  title,
  subtitle,
  type,
  data,
  options,
  actions,
  selection,
  onClick,
  extensions
});
```

### Shared toolbar and controls

A single control system owns:

- segmented buttons;
- chart mode buttons;
- icon buttons;
- dropdown menus;
- reset and export actions;
- focus, hover, active, and disabled states;
- keyboard behavior;
- responsive wrapping.

### Shared state contract

All tables and charts use the same state names:

- `loading`
- `ready`
- `empty`
- `error`
- `selected`
- `dimmed`
- `collapsed`

## Data ownership

Existing business calculations remain in their current data/controller layer until separately refactored. The rebuild consumes prepared rows, datasets, labels, and callbacks.

The shared UI layer must not change:

- TAT eligibility calculations;
- OTP calculations;
- remake calculations;
- customer, product, department, reason, or month filter state;
- current reporting-year logic;
- current exports and saved-view semantics.

## Reference rebuild scope

The first implementation must rebuild exactly two visible components from new DOM:

1. TAT Department Summary table.
2. TAT Distribution chart.

Their legacy card/table/chart markup must not be rendered when the shared versions are active.

### TAT Department Summary requirements

- New shared card shell.
- New shared table DOM.
- Seven existing columns retained.
- Sort behavior retained.
- Plain click exclusive selection retained.
- Ctrl/Cmd/Shift additive selection retained.
- Selected-row pinning retained.
- Product child rows retained.
- Column chooser retained.
- CSV export and pop-out retained.
- No TAT-only table typography, header, padding, or border rules.

### TAT Distribution requirements

- New shared card shell.
- New canvas created by the shared chart renderer.
- Cases, Percent, and Cumulative modes retained.
- Existing business-day buckets retained.
- Existing tooltip wording retained.
- Click-to-filter retained.
- Selected and dimmed bucket states retained.
- CSV, PNG, copy-image, reset, and pop-out retained.
- No adoption of an existing Chart.js instance.
- No mutation-observer or proxy-based migration code.

## Protected custom extension

The Remake main trend chart remains a custom extension of the shared chart component. It must retain:

- Line and Bar modes;
- Cases and Units modes;
- Total and Percent modes;
- Monthly and Cumulative modes;
- custom tooltip and axis behavior;
- custom colors and emphasis;
- click-to-filter;
- selected and dimmed states;
- responsive legend and plot sizing.

Its DOM shell, controls, states, export actions, and responsive frame must still come from the shared chart component.

## Visual acceptance criteria

A shared table or chart must look like the same component family across tabs.

The following must match unless explicitly configured otherwise:

- card border and radius;
- card header height and padding;
- title and subtitle typography;
- action-button dimensions and styling;
- table header background and typography;
- table row typography, padding, and borders;
- chart legend typography and placement;
- chart axis and grid styling;
- tooltip styling;
- loading, empty, and error presentation;
- responsive behavior.

Purposeful differences are allowed only through documented configuration such as column count, chart type, title text, selected colors, child rows, or protected extensions.

## Functional acceptance criteria

Before a reference component is considered migrated:

- data renders with nonzero rows or points when source data exists;
- all existing controls work;
- click filtering works;
- additive multi-selection works where previously supported;
- reset clears component-owned selection;
- filter pills update correctly;
- export content is correct;
- pop-out content matches the component;
- tooltips remain correct;
- resize and mobile layouts remain usable;
- no duplicate IDs are introduced;
- no console errors occur.

## Repository validation gates

The reference rebuild cannot be pushed to `/dev` unless:

1. `npm.cmd run audit:dashboard` passes.
2. The component registry validator passes.
3. No adapter, proxy, mutation-observer migration, or legacy-wrapper code is present.
4. The new TAT Department and TAT Distribution components are marked as shared in the registry.
5. Legacy markup for those two components is disabled or removed from the active render path.
6. Exact committed files are fetched and syntax-checked before browser testing.

## Migration order

1. Build the shared card shell.
2. Rebuild TAT Department Summary from new DOM.
3. Rebuild TAT Distribution from new DOM.
4. Browser-test the two reference components.
5. Rebuild Remake main trend as the protected extension.
6. Migrate remaining Remake components.
7. Migrate remaining TAT components.
8. Migrate Overview components.
9. Remove inactive legacy markup and visual CSS.
10. Run full browser regression.
11. Bump footer/version in the same final release commit.
12. Merge to `refactor/flatten-index`, clasp-push, and verify `/dev`.

## Definition of done

v6.544 is complete only when all 13 tables and 14 charts are rendered through the shared component system, all required interactions are retained, legacy visual implementations are removed from the active render path, browser regression passes, and the deployed footer reports v6.544.
